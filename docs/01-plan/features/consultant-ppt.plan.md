| **Core Value** | 컨설턴트가 과제 정의부터 슬라이드 본문·차트 메시지까지 일관된 맥락으로 AI와 작업하고, 자기만의 프롬프트를 쌓아 재사용할 수 있다. |

## 1. Overview

### 1.1 Purpose
컨설턴트가 PPT(보고서 덱)를 만들 때 쓰는 프롬프트 세트와, 그 프롬프트들을 단계적으로 연결해 쓰는 워크플로우 기능을 prompt-builder에 추가한다.

### 1.2 Background
- 기존 앱: 45개 프롬프트, 폼 → 실시간 미리보기 → 복사. PART 5에 PPT 프롬프트 2개(5-3 메시지·구성, 5-4 회사 스타일)가 있으나 컨설팅 덱 제작 흐름은 없음.
- 사용자 요청(2026-10-03): 범위는 **덱 기획(스토리라인·목차)** + **슬라이드 작성(액션 타이틀·본문·차트)**. 고도화 방향은 **단계별 워크플로우, 컨설팅 프레임워크 선택, 프로젝트 공통 정보 저장, 내 프롬프트 추가·편집** 4가지 모두.

### 1.3 Related Documents
- `docs/01-plan/features/prompt-builder.plan.md`, `docs/02-design/features/prompt-builder.design.md`
- Design: `docs/02-design/features/consultant-ppt.design.md`

## 2. Scope

### 2.1 In Scope
- **콘텐츠**: PART 8 "컨설팅 PPT 만들 때" 8개 프롬프트
  - 워크플로우 "덱 제작" 6단계: ① 과제 정의·거버닝 메시지 → ② 스토리라인·목차 → ③ 고스트 덱 → ④ 슬라이드 본문 → ⑤ 데이터→차트 메시지 → ⑥ 이그제큐티브 서머리
  - 단독 2개: 액션 타이틀 다듬기, 스토리라인 리뷰(So what·MECE 점검)
  - (v0.2 추가) 검토·발표 3개: 슬라이드 비판적 리뷰, 발표 스크립트·시간 배분, 예상 질문·반론 대응 — 사용자 요청(2026-10-03)으로 범위 편입
- **워크플로우**: 스테퍼 UI, [다음 단계] 이동 시 같은 키의 값 자동 전달, "이전 단계 AI 결과 붙여넣기" 필드
- **프레임워크 선택**: 필드 타입 `select`(datalist) — 피라미드 원칙, SCQA, MECE 이슈 트리, 3C, 4P, 5 Forces, SWOT, As-Is/To-Be, 옵션 평가 매트릭스 등 + 직접 입력
- **프로젝트 공통 정보**: 클라이언트, 산업, 프로젝트 목적·범위, 보고 대상, 보고 유형·분량, 톤 — 한 번 저장하면 `project` 타입 필드에 자동 삽입(개별 수정 가능)
- **내 프롬프트**: PART "내 프롬프트"에 추가·편집·삭제, `[빈칸]` 문법으로 작성하면 필드 자동 생성, JSON 내보내기·가져오기
- 데이터 스키마 v2(하위 호환)와 빌드 스크립트 검증 확장

### 2.2 Out of Scope
- AI API 호출로 단계 결과를 자동 전달(사용자가 붙여 넣는 방식 유지)
- PPT 생성 도구 전용 출력(Gamma·Copilot 입력 형식) — 후속 과제
- 서버 동기화, 계정

## 3. Requirements

### 3.1 Functional Requirements
| ID | 요구사항 | 우선순위 |
|----|----------|:--:|
| FR-01 | PART 8 프롬프트 8개를 기존 목록·검색·폼·복사 흐름에서 동일하게 사용 | P0 |
| FR-02 | 워크플로우 프롬프트 상세에 스테퍼(1/6 …)와 [이전 단계]/[다음 단계] 버튼 표시, 이동 시 같은 key의 입력값을 다음 단계에 자동 채움(비어 있을 때만) | P0 |
| FR-03 | `previous` 타입 필드: "이전 단계 AI 결과" 멀티라인 입력, 안내 문구 포함 | P0 |
| FR-04 | `select` 타입 필드: 옵션 목록 + 직접 입력(datalist) | P1 |
| FR-05 | 프로젝트 정보 패널: 6개 항목 저장(localStorage), `project` 타입 필드가 비어 있으면 자동 삽입, 패널에서 수정 시 즉시 반영 | P0 |
| FR-06 | 내 프롬프트: 생성/편집/삭제 모달, `[빈칸]`→필드 자동 추출, 목록에 "내 프롬프트" PART로 표시, JSON 내보내기·가져오기 | P1 |
| FR-07 | 기존 45개 프롬프트와 저장값은 변경 없이 그대로 동작(하위 호환) | P0 |
| FR-08 | 모든 PPT 프롬프트 템플릿은 [역할]/[업무 배경]/[요청 사항]/[출력 형식] 구조 유지, 프레임워크·프로젝트 정보가 본문에 자연스럽게 삽입 | P0 |

### 3.2 Non-Functional Requirements
- 여전히 빌드·서버·외부 라이브러리 없음, `file://`에서 동작
- 데이터 스키마 변경은 선택 속성 추가만(기존 JSON 무수정)
- 모바일 폭에서 스테퍼·모달 사용 가능

## 4. Success Criteria

### 4.1 Definition of Done
- [ ] `data/parts/part-8.json` 8개 항목, 빌드 스크립트 검증 통과(플레이스홀더↔필드, select 옵션 존재, project 키 유효)
- [ ] 브라우저: 1단계 입력 → [다음 단계] → 2단계에 프로젝트 정보·공통 키 값이 채워짐
- [ ] 프로젝트 정보 패널에서 클라이언트명 수정 → 열려 있는 프롬프트 미리보기 즉시 반영
- [ ] 내 프롬프트 생성 → 목록에 표시 → 폼 입력 → 복사 → 편집 → 삭제, 새로고침 후 유지
- [ ] 기존 45개 중 임의 3개가 이전과 동일하게 동작, 콘솔 에러 0

### 4.2 Quality Criteria
- PPT 프롬프트는 컨설팅 실무 용어(거버닝 메시지, 액션 타이틀, 고스트 덱, So what)로 작성하고 출력 형식이 표·목록으로 구체적일 것

## 5. Risks and Mitigation
| 리스크 | 영향 | 대응 |
|--------|------|------|
| 스키마 확장으로 기존 렌더링 깨짐 | 45개 프롬프트 회귀 | 모든 신규 속성은 optional, 기본값은 기존 동작 |
| 단계 간 "AI 결과" 수동 붙여넣기 번거로움 | 워크플로우 체감 가치 하락 | 다음 단계 진입 시 안내 토스트 + previous 필드를 폼 최상단에 배치 |
| 커스텀 프롬프트 템플릿 오류(`[` 불균형 등) | 필드 추출 실패 | 저장 전 미리보기로 추출된 필드 목록 표시, 0개면 경고 |
| localStorage 용량(5MB) | 커스텀 프롬프트 다수 | 내보내기 제공, 용량 초과 시 토스트 |

## 7. Architecture Considerations

### 7.1 Project Level Selection
Starter 유지.

### 7.2 Key Architectural Decisions
- 필드 타입 확장: `type: "text" | "select" | "project" | "previous"` (기본 text)
- 워크플로우는 데이터 속성(`workflow: {id, step, total}`)으로만 표현, 앱은 같은 id의 step 순서로 체인 구성
- 커스텀 프롬프트는 `PROMPTS`와 동일 스키마로 localStorage에 저장, 로드 시 병합
- 값 해석 우선순위: 사용자 입력 > 프로젝트 정보(project 타입) > 빈 값(`[확인 필요]`)
